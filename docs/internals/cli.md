# CLI

`orch` is a cobra command tree (`internal/cli`). Commands that need orchd dial its socket; those
marked *operator-only* refuse when `ORCH_TASK_ID` is set (inside a queued task).

| Command | Purpose |
|---|---|
| `version`, `ping` | build version; orchd reachability |
| `status [--json]` | whole-system report, including the `safety-net` line; works with orchd down; always exits 0. Under an applied spaces policy its `spaces` section (SP-031) lists the spaces the caller may see with the chunks each holds and how many are not yet relabelled, the relabel progress (chunks labelled by the applied revision), drift (`none` when there is none), how many sources and chunks quarantine holds (SP-028, counts only) and the live sessions in a conflict. orchd counts at most every 30 s and narrows the answer to the caller: Orch.app sees every space, the totals over every collection and the conflicts; anyone else, the CLI included, only its own space and public ones ([daemon.md](daemon.md#spaces-counts)) |
| `check` | pass/fail preconditions: ONNX Runtime dylib, embedding model, `gh auth status`, orchd ping |
| `config get\|list`, `config reset [key...] [--all]` | read settings, or put them back to their defaults (no `set`: they change through orchd, in Orch.app or with the commands that wrap `SetConfig`) ([config.md](config.md)) |
| `logs [-s <source>] [-n 100] [-f]` | orchd's recent log lines, from every source or one |
| `daemon status\|start\|stop\|restart` | orchd via `brew services` or launchd |
| `restart [orchd\|subsystems\|<unit>] [--list]` | bounce orchd, or restart units in place |
| `install [--apply\|--yes] [--target] [--home] [--bin-dir] [--no-model] [--no-daemon] [--no-git-hooks] [--no-app]` | set everything up in one plan: every harness found (or `--target`), and for Claude Code the pinned cc-safety-net and its guard rules, the model, git hooks, orchd ([install.md](install.md)) |
| `uninstall [--apply\|--yes] [--target] [--home] [--bin-dir] [--no-git-hooks] [--scan <folder>]... [--purge-data]` | reverse install, in reverse order, including what earlier releases installed (git hooks found in every repository orch knows of and each `--scan` folder); keeps data unless `--purge-data` ([install.md](install.md#uninstall)) |
| `mcp rag\|queue` | stdio MCP servers |
| `ingest text --source-uri <uri> [--type] [--scope] [--tag]` | store stdin |
| `search <query> [--top-k] [--scope] [--type] [--tag] [--require-tag] [--uri] [--mode] [--ranking] [--per-source] [--collection]... [--direct-messages] [--since] [--until]` | search memory; `--collection` keeps only the named collections among those the caller reads (never widens); `--direct-messages` also searches chat DMs ([memory.md](memory.md#chat-feeds)), the operator's only (`SearchDirectMessages`; while a spaces policy is applied, Orch.app's, whose Memory → Direct messages tab is the intended place, D-81) |
| `rag sources [--type] [--scope] [--prefix] [--limit] [--since] [--until] [--collection]... [--tag]... [--require-tag]...` | list stored sources; `--tag` keeps sources with any of the tags, `--require-tag` those with every one |
| `rag collections` | the collections the caller reads (`ListCollections`): name, space, chunk count, hybrid; a note on stderr while spaces are off. Never the migration backup |
| `rag browse [--type] [--scope] [--uri] [--tag] [--require-tag] [--since] [--until] [--collection]... [--limit] [--cursor]` | page through every matching chunk, unranked (`BrowseChunks`; [memory.md](memory.md#browsing-and-listing-collections)): hits on stdout as `N. "<uri>" #<chunk> ("<type>") in <collection>` with the text on one line; the match count (first page) and `more: --cursor <c>` or `end of listing` on stderr. `--limit` 1–200 (default 50). Chat direct messages are never listed |
| `rag forget <uri> --yes` | delete one source |
| `rag eval [--set] [--top-k] [--save] [--compare] [--mode] [--ranking] [--per-source] [--section] [--split] [--inject-format] [--cases] [--json]`, `rag eval add <query> <uri>… [--span] [--section]`, `rag eval seed` | retrieval golden set, scoring and paired-bootstrap comparison ([memory.md](memory.md#retrieval-evaluation)) |
| `rag why [prompt] [--cwd] [--json]` | the prompt from stdin when omitted or `-`; replay prompt context for a prompt: whether it would search, each candidate's score and verdict, the exact block, and (SP-031) the caller's space and the collections searched, as orchd decided them from the calling process (`--cwd` never changes them; `searched` in `--json`); changes nothing ([hooks.md](hooks.md#prompt-context)) |
| `rag backfill-sessions [--all [--summaries]] [--apply]` | store undated sessions again with their dates, or with `--all` every transcript still on disk, without harness text, and with `--summaries` their summaries too; only plans without `--apply` (*operator-only*; [memory.md](memory.md#transcripts-and-harness-text)) |
| `rag show <source-uri>` | print one source rebuilt from its stored chunks |
| `rag dedupe [--apply]` | delete path-keyed copies identical to a synced doc of a registered source (*operator-only*) |
| `rag reindex-keywords [--apply]` | rebuild keyword vectors for the current tokenizer, in place (*operator-only*) |
| `rag relabel [--dry-run]` | place every chunk whose `labels_v` is not the applied spaces policy revision again, and stamp it or move it with its vectors to its space's collection; content that cannot be placed goes to quarantine. Resumable; `--dry-run` places and counts only. Prints counts per transition and space names, never a source (`Relabel`, *operator-only*, refused inside harness sessions too; [memory.md](memory.md#relabel)) |
| `quarantine list` | the sources in [quarantine](memory.md#quarantine) with their chunk count, type and last store, then the totals (`ListQuarantine`, *operator-only*, refused inside harness sessions too) |
| `quarantine assign <source_uri> <space> --confirm` | move a quarantined source to a space and keep it there on later refreshes: checks the source is in quarantine (`ListQuarantine`), then asks `RetagSource` for a retag with `expect_from` quarantine, which moves the chunks without re-embedding and records the override. orchd needs `--confirm` to move anything out of quarantine; without it nothing moves (*operator-only*) |
| `quarantine purge [<source_uri>...\|--all] [--confirm]` | delete quarantined sources; without `--confirm` it only counts (orchd checks confirm). A named source not in quarantine refuses the whole purge, worded the same whether it is elsewhere or nowhere; nothing outside quarantine is deleted (`PurgeQuarantine`, *operator-only*) |
| `rag migrate-hybrid [--target] [--apply] [--rollback] [--drop-backup]` | layout migration (*operator-only*) |
| `source add\|list\|remove\|refresh [--confirm-prune]`, `repo add\|list` | cadence-refreshed sources; `--confirm-prune` lets the next refresh of one source prune past the cap (through orchd, operator-only) |
| `docs add\|list\|owners list\|status\|sync [--confirm-prune]\|refresh\|remove`, `docs purge <owner> [repo...] [--confirm]` | GitHub owners' markdown; `purge` deletes the indexed docs of repos an owner no longer covers (Orch.app only under a spaces policy, D-77) |
| `dispatch <body> [--agent] [--cwd] [--kind] [--model]` | queue a task (refused inside a task) |
| `tasks [--status] [--agent] [--limit] [--stats]`, `task <id> [--rate]` | task ledger; rating refused inside a task |
| `model fetch\|refresh\|list\|enable\|disable\|tier`, `provider list\|enable\|disable` | embedding model and model registry (changes *operator-only*) |
| `routing show\|evaluate\|apply\|rollback\|set\|clear` | routing table (changes *operator-only*) |
| `qdrant status\|cutover\|migrate <new-storage-dir>` | vector store engine |
| `github scopes [--refresh] [--json]`, `github enable <owner> [--all-items\|--everything-in <repos>] [--include\|--exclude <repos>]`, `github disable <owner>`, `github teams [--refresh]`, `github repos <owner>` | choose which GitHub accounts and orgs orch monitors (enable/disable *operator-only*) |
| `spaces on`, `spaces off --confirm` | the [spaces switch](daemon.md#spaces-switch), `spaces.enabled` through `SetConfig` (*operator-only*, refused inside harness sessions too; while a policy is applied only Orch.app may). `off` needs `--confirm`, because it makes quarantined content readable again. While spaces are off, `orch run` and `guard git-hook --install` are refused, and installed git hooks let everything through |
| `spaces draft\|diff [--full]\|apply --revision N [--accept-agent-draft] [--confirm-github-org]` | the spaces policy: save a draft, review it, enforce it (diff and apply *operator-only*, refused inside harness sessions too; [config.md](config.md#spaces-policy)) |
| `spaces list` | the applied spaces as the Spaces pane's Overview lists them: the policy's revision, any draft and drift, then each space's kind, GitHub orgs, roots, web prefixes, chat tenants, the spaces it reads, its terms file (never a term) and its gh login and Claude Code configuration, then where sessions under a public root write (`ListSpaces`, *operator-only*, refused inside harness sessions too; under a policy Orch.app or an unlocked terminal) |
| `spaces scan <folder>... [--offline] [--depth N]` | what the Spaces pane's setup scans: each git checkout under the folders with its GitHub owner, visibility and where the applied policy places it, each gh login's orgs, unreadable folders, and whether a limit stopped the walk. Relative folders are made absolute; reads only (`ScanSpaces`, *operator-only*) |
| `spaces terms list` | each applied space's terms file with its term count and keyed fingerprint, or why it cannot be read; never a term (`GetSpaceTerms`, *operator-only*) |
| `spaces terms set <space> < terms-file` | replace an applied space's terms file with the terms on input (never an argument), as the Spaces editor's terms field does; prints the new count and fingerprint (`SetSpaceTerms`, *operator-only*; under a policy Orch.app only, even unlocked, D-78) |
| `spaces log retention [3d\|7d\|30d]` | show or set how long ended sessions' command logs are kept (`sessions.command_log.retention`), as the Spaces pane's setup does (`GetConfig`/`SetConfig`; setting is *operator-only*, and under a policy Orch.app only, D-78) |
| `spaces why <path\|url\|owner/repo\|slack:<id>\|teams:<id>>` (alias `explain`) | how the applied policy places a target: matching roots shallowest first, the remote's effect, the deciding rule and the result (`ExplainPlacement`), including the `public_paths` pattern that made local content public (`public_path`) or that none matched (`no_public_proof`); a path starts with `/`, `~` or `.` and is made absolute before it is sent. Agents get an answer only when it names nothing but public spaces ([memory.md](memory.md#placement)) |
| `spaces log [<session>\|task:<id>\|process:<pid>] [--after N] [--limit N]` | a session's, task's or unpinned harness process's [command log](daemon.md#command-log) records in order: time, event, tool, decision and the command, directory move or gap (`ListToolEvents`). Outside any agent session any log can be read and one must be named; inside a session only its own, which is also what no argument prints. Use `session:<id>` for a session ID named like a subcommand |
| `spaces log summary [--since 168h]` | per space over the last week (or `--since`): sessions with events, tool calls, directory moves, moves into another space under the applied policy, and refusals; tasks and sessions with no space show as `-` (`SummarizeToolLog`, *operator-only*) |
| `spaces enforce [<layer> <state>] [--for 15m]` | with no arguments, every [enforcement switch](daemon.md#enforcement-switches): state, default, since when, timer and (for the operator) who set it (`GetEnforcement`). With a layer (`memory`, `guard`, `terms`, `sandbox`, `hooks`) and a state, switches it, optionally for a time (1 s to 24 h) after which it reverts (`SetEnforcement`, *operator-only*, refused inside harness sessions too); prints what the hooks switch did to Claude Code's settings. `orch status` names every layer that is off, and since when, in its `spaces` section |
| `spaces retag <source_uri> <space> [--confirm] [--expect-from <space>]` | move one source's stored chunks with their vectors to `<space>` (a space of the applied policy, or `quarantine`) and record a sticky override that later docs syncs, sources refreshes and the operator's re-ingests honor; a session's re-ingest honors it only from the target space (RC-850). Moves into a public space, out of an isolated one, or out of quarantine into a space need `--confirm`; `--expect-from` refuses unless the source is stored in that space now. Prints the chunks moved and the spaces it was in (`RetagSource`, *operator-only*, refused inside harness sessions too; [memory.md](memory.md#retag)) |
| `spaces unlock [--for 15m] [-- <command>]` | asks Orch.app to confirm operator scope for this process and what it starts (SP-077, [operator unlock](daemon.md#operator-unlock)); waits up to 2 minutes (Ctrl-C withdraws the request), then reads the code Orch.app shows from the terminal (`/dev/tty`, never standard input; a wrong code is asked for again, up to orchd's three tries), then runs `$SHELL` (or the command after `--`) as its child and ends the unlock with `Lock` when it exits. `--for` is 1 s to 60 m, default 15 m (`RequestUnlock`, `ProveUnlock`; refused inside harness sessions and tasks, and with no policy applied) |
| `spaces lock` | ends the unlocks covering this process (`Lock`) |
| `spaces terms rules [list\|enable <id>\|disable <id>\|add <kind>\|remove <id>]` | with no arguments or `list`, the [outbound rules](hooks.md#outbound-rules) (SP-075): every baseline rule and added rule by id, kind, state and what it does, the rules revision and (for the operator) who changed them and the recent changes, a warning when the rules cannot be read or the terms layer is off (`ListOutboundRules`). `enable`/`disable` switch a baseline or added rule, `add command\|destination\|fail_closed` adds a stricter rule, its value read from the first line of input (never an argument, so it stays out of shell history, the process list and a session's command log), and prints its new id, `remove` removes an added rule (`ChangeOutboundRule`, *operator-only*, refused inside harness sessions too). A rule's value is never printed. `orch spaces enforce terms off` turns the whole check off |
| `spaces sandbox [auto\|on\|off]` | with no argument, the [sandbox setting](daemon.md#sandbox-setting) (D-61): its value, what it does now and (for the operator) who set it (`GetEnforcement`). With a value, sets it (`SetSandboxSetting`, *operator-only*, refused inside harness sessions too). `auto` (default) writes orch's sandbox rules only for sessions another isolated space's folders, or another space's own `gh_config_dir` or `claude_config_dir`, or the default gh login's folder (D-69), are denied to, `on` for every space while a policy is applied, `off` never. `orch status` shows it in its `spaces` section; it never marks a session's start digest as enforcement off, but a session's next start digest names it once after each change and after each orchd start while it is off (D-68) |
| `spaces log verify <session\|task:<id>\|process:<pid>>` | recompute a session's, task's or unpinned process's [command log](daemon.md#command-log) hash chain and list every modified, missing or moved record, and every anchor that disagrees with its copy in `orch.db`; exits non-zero when broken (`VerifyToolLog`, *operator-only*) |
| `guard git-hook (--install\|--uninstall) [--apply] [--repo] [--hooks-dir] [--orch]`, `guard run commit-msg\|pre-push` | the [git hooks for outbound terms](install.md#git-hooks-for-outbound-terms): add or remove orch's `commit-msg` and `pre-push` hooks (dry run without `--apply`; `--install` is refused while spaces are off); `guard run` is what the installed hooks call |
| `run <space> [--force] -- claude\|codex [args...]` | start a harness session with the space's rules from any folder: `--settings` JSON (Claude Code) or `-c` permissions profile (Codex) and the space's `TMPDIR`, plus `CLAUDE_CONFIG_DIR`/`GH_CONFIG_DIR` only when the space names a `claude_config_dir`/`gh_config_dir` (D-59), set for the harness only; refuses a space not in the applied policy and a folder another space holds unless `--force` (reads the policy through `DiffSpaces`, so *operator-only*; [install.md](install.md#per-space-harness-settings)) |
| `spaces replay <session\|task:<id>\|process:<pid>> [--policy <rev\|file>] [--mode M] [--all]` | [policy replay](daemon.md#policy-replay): orchd decides the log's recorded tool calls again with the guard's own `Decide` and lists each call whose verdict or rule differs from the recorded one, with both rule ids; counts calls replayed, compared, changed, with no recorded verdict, and not decided (their revision no longer verifies). Each call is decided under the revision applied when it was recorded unless `--policy` names a saved revision (digits) or a policy file; `--mode` judges in `off`, `log`, `block-other-jobs` or `strict` (default: the guard switch); `--all` lists every call (`ReplaySpaces`, *operator-only*, refused inside harness sessions too). Changes nothing |
| `spaces replay <payloads.jsonl\|folder> --policy <file> [--mode M] [--all]` | the same over recorded hook payload files (the SP-001 fixtures in `internal/hook/testdata/payloads`), in the CLI without orchd: each session is pinned to the space of its first directory, targets are read from each payload as orchd reads a live call's, the guard protects what orchd's does (`spaces.GuardProtection`: orch's directories from `ORCH_CONFIG_DIR`/`ORCH_DATA_DIR`, the home, the binaries beside `orch`, the policy's terms files; RC-110), and the mode defaults to `block-other-jobs`. An argument holding `/` or `.` is a path. Open to every caller: it reads only the files named, never orchd's log or stored revisions; only regular files are read, at most 50,000 calls per file. Payloads carry no recorded verdict, so `--all` lists the verdicts; `TestSpacesReplayFixtures` runs this in CI and compares it with `internal/cli/testdata/replay/fixtures.golden` |
| `sessions list [--all]` | pinned claude and codex sessions with harness, session, PID, space, pinned directory, state (`active`, `idle`, `ended`, `unpinned`), last activity, tool events and refusals; ended ones only with `--all`; running harness processes with no pin as `unpinned`, with the tool events their own command log chain holds (with `--all` also those of unpinned processes since exited). Outside any agent session every session is shown, inside one only that session's row ([session liveness](daemon.md#session-liveness), `ListSessions`) |
| `settings list [--provider] [--kind] [--json]`, `settings enable\|disable <kind> <id> [--provider]` | managed Claude Code hooks, permissions and plugins and cc-safety-net rules: list with state and origin, turn one on or off (enable/disable *operator-only*; [settings.md](settings.md)) |
| `prs [--blocked\|--ready\|--needs-me] [--json]` | cached status of PRs in your enabled GitHub scopes (never calls `gh`); `--needs-me` lists what needs you, most urgent first |
| `prs watches` | the PRs orchd watches for review: state, what each may post, verdict and note, including why a watch ended (merged or closed, or the 14-day limit), and the review setup when it is not the default (`ListPRReviews`) |
| `prs stop <pr-url> [--forget]` | stop watching a PR, or also delete its verdict (`StopPRReview`); says how to cancel a review still running (*operator-only*) |

Every Spaces pane action in Orch.app has a CLI equivalent above (SP-055):
`internal/cli/testdata/spaces_pane_parity.json` maps each to its commands and to who may run them,
and `TestSpacesPaneParity` fails when a pane action has none ([app.md](app.md#spaces-palette-companion-and-cli-parity-sp-055)).
The CLI can draft and read; under a policy, what weakens protection stays Orch.app's (D-78).

## MCP tools

| Server | Tool | Parameters |
|---|---|---|
| `rag` | `rag_search` | query, top_k (5), scope, source_type, tags (any), all_tags, source_uri, mode, per_source, since, until |
| `rag` | `rag_ingest_text` | text, source_uri, source_type (`manual`), scope; same URI replaces |
| `rag` | `rag_list_sources` | source_type, scope, uri_prefix, limit (50), since, until |
| `rag` | `rag_delete_source` | source_uri, confirm (must be true) |
| `queue` | `queue_dispatch` | body, agent (`dev`), cwd, task_kind, model; refused inside a task |
| `queue` | `queue_list`, `queue_read` | status, agent, limit (20); id |
| `queue` | `model_recommend` | task_kind |

Numeric arguments are clamped (negative → default, above 10000 → 10000); orchd still rejects a
search `top_k` above 100. Results are plain text;
search hits read `N. [score] "<uri>" ("<type>") · <when> · <trust label>` (URI and type quoted)
followed by the chunk text fenced as quoted data, in every tier, with instruction-like text
flagged ([hooks.md](hooks.md#prompt-context)). `rag_list_sources` quotes every stored field (URI,
type, scope, tags), and so does `orch search` (URI and type, with the text on one line).
